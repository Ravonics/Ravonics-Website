## 1. Style Preamble

### The First-Light Look (the only acceptable grade)

Every generated photo must read as a **real editorial/photojournalistic photograph**, not concept art, not a render, not obviously AI. The homepage `slider/a2` (drone swarm at dusk) is the tonal anchor.

**Grade:** warm golden-hour / first-light — cool teal-blue shadows, rich amber/gold highlights, soft atmospheric haze, fine film grain, gentle lens flare, shallow depth-of-field. Low camera angle preferred. Practical ambient light only (no studio strobes). Understated, confident, federal-appropriate.

**Preferred subjects:** real hardware (antennas, server racks, circuit boards at macro, optical instruments, cables, lab equipment), real environments (server rooms, outdoor operations, waterways, lab benches, fog-lit runways, open skies), human craft moments (hands adjusting equipment, operator at a simple terminal, technician at a workbench). Motion blur acceptable. Negative space valued.

### Banned Clichés — Do NOT generate any of these
- Glowing blue neural-network brains / AI brain renderings
- Holographic globes / floating 3D HUD interfaces
- Screen-wall control rooms
- Circuit-board macro fills (as full-bleed background — small insets OK)
- Hexagon overlays / tessellation patterns
- Robot dogs in desert
- Quantum "chandelier" / suspended atom spheres
- Generic stock soldier silhouette
- Glowing eyes / anthropomorphic AI face
- Satellite dishes at night with star trails (too cliché)

### Dimension-Match Rule
New files must be **exactly the same pixel dimensions** as the current file they replace. The template CSS sizes elements by percentage — swapping a 1000x1000 for a 1920x800 would break layout.

### avif+webp Pairing Rule
- Where the current markup uses `<picture>` with `.avif` source + `.webp` fallback (e.g. `misc/s1.avif` + `misc/s1.webp`) → generate at full resolution, encode to **both** `.avif` and `.webp`.
- Where current markup is a plain `<img src="*.webp">` or `data-bgimage url(*.webp)` only → generate `.webp` only (avif not needed unless the page also has a `<link rel="preload">` for avif).
- The codex exec command generates a PNG. Post-processing encodes to webp via `cwebp` and to avif via `avifenc` (both already on the system per prior sessions). Always output to the correct dimensions.

### Naming Scheme
New unique per-page files follow this pattern:
- **Subheader backgrounds:** `images/background/<page-key>.webp` (+ `.avif` where preloaded)
- **Half-panel section backgrounds (s7 replacements):** `images/sections/<page-key>-panel.webp`
- **Capability feature photos (s3 replacements):** `images/sections/<page-key>-feature.webp`
- **About/company feature photos:** `images/sections/about-hero.webp`, `images/sections/about-inset.webp`, `images/sections/about-secondary.webp`
- **Blog-single article image:** `images/sections/blog-single-article.webp`
- **Partnerships intro photo:** `images/sections/partnerships-feature.webp`
- **Social OG images:** `images/og-image.jpg`, `images/twitter-image.jpg`
- Temp codex PNG targets: `/tmp/ravonics/<name>.png` (then encoded to webp/avif and moved to repo)
